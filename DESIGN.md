# Toss Design System

> **Korean fintech super-app — calm, confident, optimistic**

---

## Overview

Toss (토스) is South Korea's leading financial super-app — a mobile-first platform where millions manage money, transfer funds, check credit scores, and pay bills. The design system reflects the brand's core promise: making finance feel effortless.

The emotional response Toss aims to evoke is **calm confidence**. Financial interfaces are historically anxiety-inducing — dense tables, confusing jargon, alarmist reds. Toss inverts this with a palette of serene blues, generous whitespace, and a custom typeface that feels both approachable and authoritative. Every pixel communicates: *your money is safe here.*

The system is anchored by Toss Blue (`{colors.primary}`), a shade that balances trustworthiness (the stability banks use) with digital-native freshness. The overall mood is optimistic but restrained — no gratuitous gradients, no decorative flourishes that don't serve the financial task at hand. This is a design system built for speed, clarity, and emotional reassurance at scale.

## Colors

### Brand & Accent

Toss Blue (`{colors.primary}`) is the singular brand anchor — a vivid yet controlled cerulean that communicates financial trust without feeling conservative. It appears on primary CTAs, active navigation states, and key data highlights. Unlike traditional banking blues that lean navy or muted, Toss Blue is digitally native — it glows on screens without overheating.

**The Toss Blue Gradient:** Hero sections use a blue-to-ice gradient from `{colors.hero-warm}` through `{colors.hero-glow}` to `{colors.hero-pink}` — a progression from solid Toss Blue to a luminous, airy tone that evokes clarity and transparency. This is the brand's most expressive moment, reserved for onboarding, marketing pages, and celebratory states.

Supporting accent colors follow fintech conventions but with Toss's characteristic restraint:
- `{colors.badge-success}` — A fresh green for completed transactions, verified badges, and positive financial milestones
- `{colors.badge-warning}` — Warm amber for cautionary states and pending confirmations
- `{colors.badge-info}` — Teal for informational prompts and feature discovery

The link color (`{colors.link}`) mirrors the primary blue, ensuring every clickable element carries brand consistency.

## Typography

### Font Family

Toss uses **Toss Product Sans** as its proprietary typeface — a custom font designed specifically for the Korean fintech ecosystem. It blends the clarity required for financial numerals with the warmth needed for everyday consumer finance.

The full font stack:
```
"Toss Product Sans", "Tossface", "SF Pro KR", "SF Pro Display",
-apple-system, BlinkMacSystemFont, "Basier Square",
"Apple SD Gothic Neo", Roboto, "Noto Sans KR", sans-serif
```

This stack prioritizes Toss's own typeface, then falls through Apple's Korean-optimized SF Pro KR (for iOS users), through cross-platform system fonts, to Google's Noto Sans KR for ultimate Korean character coverage. The inclusion of "Tossface" — Toss's emoji font — ensures branded emoji rendering within the app.

For code and monospaced contexts, Toss uses:
```
"SF Mono", SFMono-Regular, Menlo, Consolas, monospace
```

### Hierarchy

| Token | Size | Weight | Line Height | Letter Spacing | Use |
|-------|------|--------|-------------|----------------|-----|
| display-xl | 30px | 700 | 1.33 | normal | Hero headline — one per page |
| display-lg | 26px | 700 | 1.38 | normal | Section openers, feature titles |
| heading-lg | 22px | 700 | 1.36 | normal | Content section headings |
| heading-md | 20px | 600 | 1.4 | normal | Card titles, modal headings |
| heading-sm | 20px | 700 | 1.4 | normal | List headers, feature card titles |
| subtitle | 16px | 600 | 1.5 | normal | Lead paragraphs, description text |
| body-lg | 16px | 400 | 1.5 | normal | Marketing prose, feature descriptions |
| body-md | 14px | 400 | 1.57 | normal | Default body — the workhorse text style |
| body-sm | 13px | 400 | 1.54 | normal | Captions, metadata, timestamps |
| button-md | 16px | 600 | 1.5 | normal | Primary button labels |
| button-sm | 14px | 600 | 1.5 | normal | Secondary/compact button labels |
| caption | 12px | 400 | 1.5 | normal | Footer text, legal disclaimers |
| code-md | 14px | 400 | 1.57 | normal | Code blocks, formatted data |
| code-sm | 13px | 400 | 1.5 | normal | Code tabs, inline code |

### Principles

**The Body-MD Workhorse:** At 14px with 1.57 line height, `{typography.body-md}` is the most used style in the system — transaction histories, account lists, feature descriptions. The elevated line height (1.57 vs the more common 1.5) improves readability of Korean mixed-script text (Hangul + Hanja + English numerals) at small sizes.

**The Semibold Button Rule:** Buttons use 600 weight (semibold) — never 700 (bold). This keeps button labels substantial enough to read at a glance without feeling heavy or alarmist. In a financial app, buttons should invite taps, not trigger anxiety.

**Narrow Weight Range:** Toss uses only three weights — 400 (normal), 600 (semibold), 700 (bold). No thin (300) or light (100) weights exist in the system. This ensures text is always legible across the millions of Android and iOS devices Toss runs on.

**Tabular Numerals for Financial Data:** When displaying monetary values, account numbers, or transaction amounts, use `font-variant-numeric: tabular-nums` to ensure all numerals occupy equal width. This is critical for proper alignment in financial tables and money transfer UIs.

### Note on Font Substitutes

When "Toss Product Sans" is unavailable (third-party integrations, web views, email templates), the fallback stack prioritizes `SF Pro KR` (Apple ecosystem) then `"Apple SD Gothic Neo"` (Korean-optimized system font) then `"Noto Sans KR"` (cross-platform Korean support). The sans-serif generic guarantees the interface remains readable even in degraded environments.

For environments where custom fonts cannot be loaded at all (AMP pages, plain-text fallbacks), the system uses the native system font stack (`-apple-system, BlinkMacSystemFont, sans-serif`) which automatically selects the platform's most legible Korean font.

## Layout & Spacing

### Spacing Scale

Toss uses a 4px base grid that doubles at each step, creating a rhythm suited for information-dense financial interfaces:

| Token | Value | Usage |
|-------|-------|-------|
| xxs | 2px | Hairline borders, micro adjustments |
| xs | 4px | Icon-to-text gap, inline badge margins |
| sm | 8px | Tight spacing within compact rows |
| md | 12px | Default inset, element groups |
| lg | 16px | Card inset, section internal padding |
| xl | 24px | Card padding, modal internal margin |
| xxl | 32px | Section internal, component clusters |
| xxxl | 48px | Feature spacing, large card groups |
| section | 96px | Between major page sections |
| band | 160px | Maximum separation — page hero to content |

### Grid

Toss follows a **375px mobile-first** grid system, reflecting its origins as a mobile super-app. All layouts are designed at 375px base and scale up to tablet (768px) and desktop (1280px) breakpoints.

Content containers use a 20px outer gutter on mobile (scaling to 24px on tablet, 32px on desktop). The grid column count shifts from 4 columns (mobile) to 8 columns (tablet) to 12 columns (desktop), but the underlying spacing scale remains consistent at every breakpoint.

### Whitespace Philosophy

**"Breathe around the numbers."** Financial data needs breathing room. Toss deliberately uses generous spacing (`{spacing.xl}` and `{spacing.xxl}`) around monetary values, account balances, and transaction amounts. This prevents the visual claustrophobia common in traditional banking interfaces and makes scanning for numbers effortless.

Section-level spacing (`{spacing.section}` and `{spacing.band}`) creates clear visual chapters. On a money-transfer flow, for example, `{spacing.section}` separates "from account" from "to account" from "amount" — creating visual boundaries that replace the need for heavy borders or background changes.

## Elevation & Depth

Toss uses a minimal, pure-black-opacity shadow system. Unlike themes that rely on colored shadows (blue glows, warm tints), Toss shadows are always pure black at varying opacities — a deliberate choice that keeps the system neutral and the focus on content.

### Level Table

| Level | Treatment | Use Case |
|-------|-----------|----------|
| Level 0 | `{elevation.level0}` — No shadow | Page background, text blocks, flat surfaces |
| Level 1 | `{elevation.level1}` — 0px 1px 3px rgba(0,0,0,0.06) | Default cards, subtle surface separation |
| Level 2 | `{elevation.level2}` — 0px 2px 8px rgba(0,0,0,0.08) | Hovered cards, elevated controls |
| Level 3 | `{elevation.level3}` — 0px 4px 12px rgba(0,0,0,0.12) | Modals, popovers, dropdown menus |
| Level 4 | `{elevation.level4}` — 0px 8px 24px rgba(0,0,0,0.16) | Toast notifications, floating action buttons |

Each level doubles the blur radius and increases opacity progressively — creating a natural-feeling depth curve. Level 1 is barely perceptible (the card simply "exists"), while Level 4 creates clear separation for modal overlays.

Dark mode elevates all shadow opacities to compensate for the dark background:
- Level 1 dark: 0px 1px 3px rgba(0,0,0,0.40)
- Level 2 dark: 0px 2px 8px rgba(0,0,0,0.50)
- Level 3 dark: 0px 4px 12px rgba(0,0,0,0.55)
- Level 4 dark: 0px 8px 24px rgba(0,0,0,0.60)

### Decorative Depth

Beyond functional elevation, Toss uses a **scrim overlay system** for modal and sheet backgrounds:
- `{colors.overlay}` — `rgba(2, 9, 19, 0.5)` for standard modal backdrops
- Overlay Heavy — `rgba(2, 9, 19, 0.91)` for full-screen sheet backdrops

In dark mode, the scrim shifts to pure black at equivalent opacities, ensuring consistency with the dark canvas.

## Shapes

### Border Radius Scale

Toss uses a precise, stepped radius system where each level corresponds to a specific component type:

| Token | Value | Usage |
|-------|-------|-------|
| none | 0px | Navbars, full-bleed sections, hero bands |
| xs | 2px | Micro tags, progress track backgrounds |
| sm | 4px | Text inputs, selects, checkboxes, badges, tabs |
| md | 8px | Buttons, alerts, primary interactive elements |
| lg | 12px | Cards, modals, panels |
| full | 9999px | Avatars, radio buttons, switches, progress bars, pills |

**The Toss Radius Rule:** Interactive elements use `{rounded.md}` (8px) — generous enough to feel modern and friendly, controlled enough to avoid the frivolousness of pill-shaped buttons in a financial context. Data containers (cards, modals) use `{rounded.lg}` (12px) for more pronounced framing. Selection controls (radio, switch) use `{rounded.full}` (9999px) for clear binary state indication.

### Photography Geometry

- **Avatar thumbnails:** Circular via `{rounded.full}`, 40px × 40px for standard, 64px × 64px for profile headers
- **Hero section images:** 16:9 aspect ratio, full-bleed width, `{rounded.none}` for immersive banners
- **Card thumbnails:** 4:3 aspect ratio, `{rounded.lg}` top corners to align with card container radius
- **Contribution/activity avatars:** Circular, 24px × 24px for compact list views
- **Product screenshots:** 9:16 aspect ratio (mobile-first), `{rounded.lg}` corners

## Components

### Buttons & Interaction

**Button Primary** — The primary financial action (send money, pay bill, confirm transfer)
- Background `{colors.primary}`, text `{colors.on-primary}`, type `{typography.button-md}`
- rounded: `{rounded.md}`, padding 12px 24px, height 44px
- Hover: Deepens to `{colors.primary-deep}` (`#2272eb`)
- Active/Pressed: Further darkens to `#1c62c9` with `transform: scale(0.98)` for tactile feedback
- Disabled: Opacity 0.5 using `{opacity.disabled}`, cursor not-allowed

**Button Primary (Dark Mode)** — Identical bg `{colors.primary}` (`#1a6fe0`) with `{colors-dark.on-primary}` (`#ffffff`) text. Hover shifts to `#155fc4`. White text is used in both modes because dark text on the AA-safe blue falls below 4.5:1.

**Button Secondary** — For secondary actions, cancellations, dismissals
- Background `{colors.secondary}`, text `{colors.on-secondary}`, type `{typography.button-md}`

## Do's and Don'ts

### Do

- **Use Toss Blue (`{colors.primary}`) for primary CTAs only** — the singular accent commands attention when used sparingly. Reserve it for money-sending, payment-confirmation, and account-creation buttons.
- **Apply `{typography.body-md}` (14px/1.57) as the default text style** — it's optimized for Korean mixed-script readability at small sizes. The elevated line height prevents Hangul characters from colliding with English numerals.
- **Use tabular numerals for financial data** — apply `font-variant-numeric: tabular-nums` on all monetary amounts, account numbers, and transaction IDs to ensure proper column alignment.
- **Use `{rounded.md}` (8px) for interactive elements** — buttons, alerts, and primary controls. It's modern without feeling frivolous, controlled without feeling sharp.
- **Use `{elevation.level1}` for default card elevation** — the barely-perceptible shadow (0px 1px 3px rgba(0,0,0,0.06)) creates clean surface separation without visual noise.
- **Use `{spacing.xl}` (24px) around monetary values** — financial figures need breathing room to prevent scanning errors.
- **Use `{colors.background-bone}` for secondary groupings** — it creates subtle visual structure without relying on shadows or borders.

### Don't

- **Don't use pure black (`#000000`) for text** — always use `{colors.ink}` (`#191f28`) in light mode or `{colors-dark.ink}` (`#e8e8e8`) in dark mode. Pure black creates harsh contrast that increases eye strain during extended financial session use.
- **Don't apply Toss Blue to large background surfaces** — it's an accent, not a canvas. Reserved for CTAs, active states, and data highlights only.
- **Don't use font weight below 400** — no thin (300), light (200), or extra-light (100) weights exist in the system. Financial text must always be legible.
- **Don't use pill-shaped (full rounded) buttons for primary CTAs** — `{rounded.md}` (8px) is the maximum. Pills feel too casual for financial actions.
- **Don't introduce additional accent colors beyond the blue/green/amber/teal system** — the four-color semantic palette (primary, success, warning, info) is complete.
- **Don't override the spacing scale** — always use the semantic spacing tokens (xs through band). Inconsistent spacing breaks the "breathe around the numbers" principle.
- **Don't use decorative gradients outside hero sections** — Toss is a financial app; visual flair is reserved for onboarding and marketing moments only.
- **Don't skip dark mode variants for interactive components** — every button, input, and control must function in both light and dark environments.

## Responsive Behavior

### Breakpoints

| Name | Width | Key Changes |
|------|-------|-------------|
| Mobile | 375px (base) | Single-column layout, 20px gutters, full-width buttons |
| Tablet | 768px | Two-column cards, 24px gutters, side-by-side form fields |
| Desktop | 1280px | Multi-column layout, 32px gutters, max-width content container (1200px) |
| Wide | 1920px | Expanded content area, multi-panel layouts, side navigation |

### Touch Targets

Financial actions demand generous touch targets to prevent costly mis-taps:

- **Primary financial actions** (send money, pay, confirm): Minimum 56px height (exceeds 44px standard) — the stakes are higher, so the target must be larger
- **Standard interactive elements** (buttons, inputs, selects): 44px height minimum per Android Material and iOS HIG guidelines
- **Icon-only buttons** (close, back, info): Minimum 44px × 44px hit area, even if the visual icon is smaller
- **Checkbox and radio**: 20px × 20px visual, 44px × 44px invisible hit area via `::before` pseudo-element

### Collapsing Strategy

- **Navigation**: Desktop horizontal navbar (60px) collapses to hamburger menu below 768px. Bottom tab bar activates on mobile for thumb-reachable navigation.
- **Data tables**: Transaction histories collapse from multi-column tables to stacked card layouts on mobile. Each row becomes a discrete card with key-value pairs.
- **Form layouts**: Side-by-side fields (expiration date + CVV on desktop) stack vertically on mobile. Single-column form flows reduce cognitive load on small screens.
- **Modal sheets**: Desktop modals center in viewport with overlay. Mobile converts to bottom sheets that rise from the screen bottom — easier for one-handed operation.

### Image Behavior

- **Hero images**: Full-bleed width, constrained height (max 40vh on desktop, 30vh on mobile), `object-fit: cover` to maintain aspect ratio
- **Card thumbnails**: Fixed 4:3 aspect ratio, `object-fit: cover`, `{rounded.lg}` top corners to match card radius
- **Avatars**: Circular crop via `border-radius: 50%`, 40px default, 64px profile, 24px compact. Serve at 2× for Retina/HiDPI displays.
- **DPR handling**: All images served at minimum 2× resolution. Critical financial imagery (checks, receipts) served at 3× for zoom-capable viewing.

## Iteration Guide

1. **Focus on one component at a time.** When adding or modifying components, isolate the work to a single component variant (e.g., "button-primary pressed" before "button-secondary hover"). Document the state before moving on.

2. **Reference tokens directly in all specifications.** Never write raw hex values (`#3182f6`) in component specs — always use `{colors.primary}`. For spacing, always use semantic tokens (`{spacing.xl}`) not pixel values (`24px`). For typography, always reference composed tokens (`{typography.button-md}`).

3. **Run contrast audit after color changes.** After modifying any color token, run the contrast audit tool against `contrast-audit.json` to verify WCAG AA compliance (4.5:1 for normal text, 3:1 for large text). Financial applications must meet accessibility standards.

4. **Add new component variants as separate entries.** Don't modify existing variants — add new ones. For example, if adding a "large" button, add `button-primary-lg` rather than modifying the existing `button-primary` anatomy.

5. **Keep brand accent scarce.** Every new use of `{colors.primary}` must be justified. Ask: "Does this element need to attract attention?" If the answer is "it's informational," use `{colors.ink}` or `{colors.body}` instead.

6. **Test dark mode immediately.** After any visual change, toggle to `data-theme="dark"` and verify the component renders legibly. Dark mode is not optional — it's a parity requirement.

7. **Validate against the 6 border-radius levels.** Ensure every component's corners use one of the 6 defined radius tokens (`{rounded.none}`, `{rounded.xs}`, `{rounded.sm}`, `{rounded.md}`, `{rounded.lg}`, `{rounded.full}`). No intermediate values.

8. **Document motion alongside appearance.** When adding interactive components, specify `{animation.duration.standard}` (250ms) and `{animation.easing.default}` for transitions. Motion is part of the component specification.

## Known Gaps

- **Full-screen modal sheets** — The current system documents center-positioned modals but not bottom-sheet variants common in mobile-finance contexts (e.g., "select bank account" sheets).
- **PIN/Password entry** — Specialized input fields for financial PINs and biometric authentication are not documented. These require distinct visual treatment (masked input, shuffled keypad, fingerprint iconography).
- **Financial chart components** — Line charts, bar charts, and spending breakdown visualizations (common in the Toss app) are not extracted as reusable component tokens.
- **Receipt/Check scanning** — Document capture and OCR feedback UI (bounding box overlay, confirmation state) is not documented.
- **Biometric authentication** — Fingerprint and Face ID enrollment flows and their visual states (scanning, success, retry) are missing from the component library.
- **Bottom tab bar** — Mobile-specific bottom navigation with icon + label, badge notification counts, and active state animation is not defined.
- **Pull-to-refresh** — The financial-data refresh interaction (with branded Toss Blue spinner and haptic feedback trigger) is not documented.
- **Empty states** — Onboarding-empty illustrations for zero-balance accounts, no-transaction-history, and feature-discovery screens are not captured in the token system.
